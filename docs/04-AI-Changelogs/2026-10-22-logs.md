## Correction (same day, follow-up commit)

The "Dead Prisma code removed" bullet above claimed "No `@prisma/*` dependency existed anywhere to
remove." **That was wrong.** It was checked against every `package.json`'s direct dependencies, but
not against `pnpm-lock.yaml`'s resolved dependency graph — `@prisma/client@6.19.3` (and
transitively `prisma@6.19.3`, `@prisma/engines@6.19.3`) are auto-installed as **optional peers of
`drizzle-orm@0.40.1`** (it lists `@prisma/client` under `peerDependenciesMeta` for optional
Prisma-schema interop, a feature this repo doesn't use). Removing their `allowBuilds: false` entries
from `pnpm-workspace.yaml` made CI's `pnpm install --frozen-lockfile` fail with
`ERR_PNPM_IGNORED_BUILDS` (PR #3) — pnpm refuses to silently skip a build script for a package with
no explicit `allowBuilds` entry. Restored all three entries (`@prisma/client`, `@prisma/engines`,
`prisma` → `false`) exactly as they were on `origin/main`, with a comment explaining why they must
stay while `drizzle-orm` is on the 0.40.x line. Verified locally: wiped every `node_modules`, fresh
`pnpm install --frozen-lockfile` exits 0 with no `ERR_PNPM_IGNORED_BUILDS`, and the full `ci.yml`
sequence (build workspace packages → typecheck → lint → test → build, both apps) passes.
