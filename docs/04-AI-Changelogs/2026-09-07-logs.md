# AI Changelog: 2026-09-07

## Summary of Actions

Multi-session production-readiness hardening pass, starting from a full read-only architectural audit and ending with linting infrastructure and Super Admin bootstrap. Four commits: `3df3cc90`, `47331c0b`, `c615ecf8`, `676f9bd8`.

- **Architectural Audit (read-only)**: Parallel review of the Drizzle schema/reports aggregation, API business logic/guardrails, frontend state invalidation, and Docker/build infra. Found (among lower-severity items): a cross-tenant IDOR and multiple broken guardrails in the inventory reverse endpoint, a hardcoded default JWT secret, no RBAC enforcement anywhere, three independently-drifting Virtual Cash Balance calculations, a cash-collection race condition, and Docker images that busted their dependency-install cache layer on every source change.
- **Reverse Endpoint Rewrite** (`apps/api/src/modules/inventory/inventory.controller.ts`): Client now sends only `{ logId, remarks }` (`ReverseEntrySchema` in `packages/validation`) — the server resolves everything else from the log itself, inside a transaction that locks the machine row. Enforces: tenant isolation, blocks reversing Cash Collect entries, restricts reversal to the single most recent Restock entry per machine, blocks double-reversal via the new `inventory_logs.reversedLogId` column, fixes a sign bug that compounded losses instead of undoing them, and replaces a silent dev-mode fake-success fallback with real HTTP error codes.
- **RBAC** (`apps/api/src/core/middlewares/rbac.ts`, new): `requireRole(...roles)` applied to machine creation, packet creation, user creation, user deactivation (all `ADMIN`-only), and inventory reversal (`ADMIN` + `FIELD_AGENT`, so agents can still self-correct in the field).
- **User Deactivation**: New `users.isActive` column, admin-only `PATCH /users/:id/status`, and a live `isActive` check in `tenantHandler` on every request (not just login) so a deactivated user's existing JWT stops working immediately. `useToggleUserStatus` (frontend) now calls the real endpoint instead of writing a fake status into the React Query cache.
- **Secrets & Infra**: Removed hardcoded fallback secrets from `server.ts`, `client.ts`, `docker-compose.yml`, and `apps/api/Dockerfile` — the API and DB client now throw and crash on startup if `JWT_SECRET`/`DATABASE_URL` are missing (verified against the built image). Rotated `JWT_SECRET` and `POSTGRES_PASSWORD` to high-entropy values via a live `ALTER USER` against the running Postgres volume (no destructive reinit needed). Postgres is bound to `127.0.0.1:5432` — reachable for host-side `drizzle-kit` tooling, never exposed on the LAN/internet (a bare `5432:5432` binds all interfaces).
- **Virtual Cash Balance Unification**: New `computeVirtualCashBalances()` / `computeVirtualCashBalanceForMachine()` (`apps/api/src/modules/machines/virtualCashBalance.service.ts`) — two batched grouped-aggregate queries, one shared formula. `GET /machines/:id`, `GET /machines`, `GET /machines/metrics`, and the cash-collection guardrail all read from it; the agent-facing machine page reads the same backend value instead of recomputing independently. See [[inventory-flow.md]] for the full before/after.
- **Cash-Collection Race Condition**: `cashCollectionHandler` now locks the machine row (`SELECT ... FOR UPDATE`) inside a single transaction before evaluating the overage guardrail, closing a double-tap exploit.
- **Docker Build Optimization**: Both Dockerfiles now copy only `package.json` manifests before `pnpm install`, then copy source separately (verified: install layer stays cached on a real source change). `pnpm prune --prod` drops devDependencies; the web image no longer copies `packages/database` (never a dependency). Both images run as the non-root `node` user. Discovered and fixed a real footgun: `pnpm run start` as the container `CMD` triggers pnpm's startup dependency-status check, which tries a live `pnpm install` against the npm registry on every boot — both Dockerfiles now invoke the compiled entrypoint directly (`node dist/server.js`, `next start`) instead. Added a `HEALTHCHECK` to the API image; `web`/`nginx` in `docker-compose.yml` now depend on `api: condition: service_healthy`.
- **ESLint/Prettier Initialized**: Flat config (`eslint.config.mjs`) at the workspace root — TypeScript rules everywhere, `eslint-config-next`'s rules (via the `FlatCompat` bridge) scoped to `apps/web` only. Pinned `eslint` to the 9.x line (not the newly-released 10.x, which `eslint-config-next`'s plugin chain doesn't yet support). `@typescript-eslint/no-unused-vars` is a warning, not an error; `no-explicit-any` is off for this first pass given how pervasively this codebase uses `any`.
- **React Hooks Ordering Fix** (`apps/web/src/app/(agent)/machine/[machineId]/page.tsx`): The unauthenticated-user early `return` sat between the component's first `useState` and its `useQuery`/`useForm`/`useMutation` calls — on mount all hooks ran (guard condition false pre-effect), but once the mount effect flipped `hasCheckedAuth` to `true`, an unauthenticated user's re-render hit the `return` *before* reaching those same hooks, changing the hook count between renders. Fixed by moving the guard to fire only after every hook has run. Also fixed 4 unescaped-JSX-quote errors, 2 empty shadcn/ui prop interfaces (disable-comment, kept as untouched boilerplate), and 2 empty catch blocks. `pnpm run lint`: 0 errors, 42 pre-existing `no-unused-vars` warnings left as warnings by design.
- **Super Admin Bootstrap** (`packages/database/src/seed.ts`): Reads `SUPER_ADMIN_EMAIL`/`SUPER_ADMIN_PASSWORD` from the environment instead of a hardcoded `admin@example.com` / `Admin1234!` — throws a fatal error if either is missing. Re-running the seed also reactivates the account (`isActive: true`) as an env-driven recovery path. No longer logs the raw password to stdout. All users beyond this one bootstrap account are created via the in-app admin UI (`POST /api/v1/users`), not this script.
- **Documentation Audit**: Updated [[database-schema.md]] (Prisma → Drizzle framing, `isActive`/`reversedLogId`), [[inventory-flow.md]] (accurate Reverse guardrails, Virtual Cash Balance unification), [[multi-tenant-saas.md]] (RBAC layer documented alongside tenant isolation), and the MoC (this file linked, Drizzle label fixed). Added root `README.md` with environment variable reference and local setup steps, including `SUPER_ADMIN_EMAIL`/`SUPER_ADMIN_PASSWORD`.
